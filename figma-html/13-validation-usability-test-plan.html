InstaCard · BCA UI/UX Test
13 · VALIDATION / USABILITY TEST PLAN · Senior evidence
Proposed validation — not claimed research results

Before polishing further, I would validate whether people understand the product and can complete the core exchange journey.

This board is intentionally framed as a validation plan. No user-test results are fabricated. The goal is to make the next research step explicit: what I need to learn, how I would test it, and what design change each failure would trigger.

Hypotheses to validate

Four assumptions carry most of the UX risk in this concept.

H1

5-second comprehension

A first-time visitor can explain “digital profile + share + save contact” without extra explanation.

H2

No-app value is understood

Recipients understand they can open and save a card without installing InstaCard.

H3

Create → Share → Save is memorable

The 3-step model matches the way people expect an exchange to work.

H4

Early Access is the obvious next action

The CTA is visible and meaningful after the value proposition is understood.

Lean moderated sessions are enough to expose comprehension and flow problems before implementation.

Tasks → success criteria → design response

Each task has a concrete signal and a predefined response if the hypothesis fails.

TaskSuccess signalPotential findingIf it fails, I would…
T1 · First impression
“What do you think this product does?” after 5 seconds.		User mentions a digital contact/profile and sharing.They think it is only a social-link page or QR generator.Rewrite hero, strengthen product visual, bring save-contact proof higher.
T2 · Recipient mental model
“You receive this card. What happens next?”		User expects browser open → review → save contact.They expect app install, account creation or manual copy.Make “No app required” more explicit and show browser/save sequence earlier.
T3 · Find the main action
“You want to try InstaCard. What would you do?”		User finds Early Access without scanning multiple competing CTAs.User clicks navigation/features first or asks where signup is.Increase CTA contrast, simplify nearby actions, reduce repetition noise.
T4 · Explain the flow
“How would you use this in a real meeting?”		User can restate Create → Share → Save.Customization becomes more memorable than the exchange outcome.Rebalance section order and reduce decorative feature emphasis.
Evidence rule: until these sessions happen, I would present all outcomes as hypotheses and expected signals — never as completed usability findings.
